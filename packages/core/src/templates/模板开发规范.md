# 模板开发规范

> 适用范围：SiteBuilder Studio 的模板中心。所有模板统一维护在 `catalog.json`，
> 装修器、公开站、后端种子、管理后台共用这一份数据，禁止在别处另建模板列表。

---

## 1. 模板是什么

**模板 = 一份预置的 `PageSchema` DSL。**

用户「套用模板」的本质是：把模板的 `schema` 深拷贝一份，写入自己站点的草稿。

核心文件：

| 文件 | 作用 |
|------|------|
| `packages/core/src/templates/catalog.json` | **唯一数据源**，模板元数据 + DSL 都在这里 |
| `packages/core/src/templates/index.ts` | 类型定义（`SiteTemplate`）、读取与 `build()` 深拷贝 |
| `server/src/database/seed.ts` | 启动时把 catalog 按 `name` 幂等写入数据库 `templates` 表 |
| `web-admin/src/components/TemplatePreview.tsx` | 模板卡片的缩略预览（由 `preview` 字段决定样式） |

> 新增模板**只改 `catalog.json` 一处**，执行 `npm run seed` 后三端自动同步。

---

## 2. 新增模板的标准流程

1. 在 `catalog.json` 数组末尾追加一个对象（结构见第 3 节）。
2. 用脚本校验字段完整性与 schema 合法性（见第 7 节）。
3. 在编辑器里「以模板新建」实际打开一次，确认画布渲染正常。
4. 发布一个测试站点，确认公开站渲染正常、图片不 404。
5. 执行 `cd server && npm run seed` 同步到数据库。
6. 刷新管理后台模板中心，确认卡片、筛选、预览都正常。

---

## 3. 模板条目字段契约（必填，缺失会导致模板中心白屏）

类型定义来自 `index.ts` 的 `SiteTemplate`：

| 字段 | 类型 | 必填 | 说明 / 示例 |
|------|------|------|-------------|
| `id` | `string` | 是 | 唯一标识，小写中划线，如 `"aurora-electronics"` |
| `name` | `string` | 是 | 模板名称，seed 按它幂等更新，如 `"AURORA 电子制造"` |
| `category` | `string` | 是 | 分类，如 `"企业"` / `"营销"` / `"户外/电商"` |
| `industry` | `string` | 是 | 行业，展示在卡片与搜索关键词中 |
| `description` | `string` | 是 | 一句话描述，参与搜索 |
| `cover` | `string` | 是 | 缩略图背景，CSS gradient 字符串 |
| `preview` | `agency\|enterprise\|landing\|blank\|generic` | 是 | 决定缩略图版式，见第 4 节 |
| `badge` | `string` | 否 | 角标，如 `"新"` / `"热门"` |
| `tags` | `string[]` | 是 | **必须存在且为数组**，搜索时用 `tags.join(' ')` |
| `usage` | `number` | 否 | 使用次数，影响「热门」筛选 |
| `isFree` | `boolean` | 否 | 是否免费，`false` 时在详情显示「付费」 |
| `schema` | `PageSchema` | 是 | 页面 DSL 本体，见第 5 节 |

**血泪教训**：曾新增模板漏写 `tags`，导致 `App.tsx` 中 `item.tags.join(' ')` 抛异常，整个模板中心白屏。所有字段宁可给空值也不能缺。

最小可用示例：

```json
{
  "id": "my-template",
  "name": "我的模板",
  "category": "企业",
  "industry": "通用",
  "description": "一个简洁的企业官网模板",
  "cover": "linear-gradient(135deg,#0B1F3A 0%,#1E5EFF 100%)",
  "preview": "enterprise",
  "badge": "新",
  "tags": ["企业官网", "响应式"],
  "usage": 0,
  "isFree": true,
  "schema": { "...": "见第 5 节" }
}
```

## 4. `preview` 取值与缩略图

`preview` 决定卡片缩略图的 HTML 版式（`TemplatePreview.tsx`），不是真实截图：

| 值 | 适用场景 |
|----|----------|
| `enterprise` | 企业官网，导航 + 图文 + 页脚的通用版式 |
| `agency` | 广告/设计公司，强调案例展示 |
| `landing` | 营销落地页，突出 CTA |
| `blank` | 空白页面，显示「空白画布」 |
| `generic` | 其它兜底版式 |

`cover` 是缩略图背景色，写完整 CSS gradient，例如：
`"linear-gradient(135deg,#060B16 0%,#1E5EFF 100%)"`

## 5. `schema` 结构规范（PageSchema）

```jsonc
{
  "version": 1,                       // 固定为 1
  "meta": {
    "title": "页面标题",
    "description": "页面描述"
  },
  "theme": {                          // 全站设计令牌，组件通过 CSS 变量引用
    "primary": "#171717",
    "accent": "#D4AF37",
    "background": "#ffffff",
    "text": "#171717",
    "muted": "#475569",
    "radius": 8,
    "fontFamily": "system-ui, ...",   // 可选
    "fontSize": 16,                   // 可选
    "lineHeight": 1.7,                // 可选
    "colors": []                      // 可选，自定义颜色令牌
  },
  "root": {                           // 必须是 container 类型
    "id": "root",
    "type": "container",
    "props": { "gap": 0, "padding": 0, "background": "#ffffff" },
    "style": {},
    "children": [ /* DslNode 数组 */ ]
  }
}
```

### DslNode 节点规范

```jsonc
{
  "id": "唯一ID",                     // 全树唯一，建议 "模块名-短标识"
  "type": "heading",                  // 必须是已注册模块 type
  "props": { /* 匹配该模块的 propertySchema */ },
  "style": { /* 可选，NodeStyle */ },
  "children": [],                     // 可选，仅容器型模块需要
  "hidden": false,                    // 可选
  "locked": false                     // 可选
}
```

- `type` 必须是注册表中存在的模块（见第 6 节），否则渲染器跳过该节点。
- `props` 的键名和值类型必须匹配对应模块的 `propertySchema`，比如 `columns` 是 number/select 字符串，`items` 是多行文本。
- 容器型模块（`container` / `grid`）才能有 `children`。

## 6. 可用模块与 props 约定

### 6.1 模块类型（注册表中的 39 个）

**基础**：`heading` `text` `button` `image` `divider` `spacer`
**布局**：`container` `grid` `image-text` `feature-list` `tabs` `vertical-tabs` `accordion` `image-tabs` `breadcrumb` `anchor-nav`
**内容**：`card-list` `article-list` `video` `download` `map` `notice` `timeline`
**营销**：`product-list` `coupon-card` `countdown` `number-counter`
**互动/表单**：`contact-form` `vote` `site-search` `online-service`
**展示**：`carousel` `navbar` `footer`
**高级**：`custom-html` `embed` `friend-links` `global-block-ref`
**插件**：`visitor-counter`

> 模板中尽量用标准模块，少用 `custom-html`。标准模块可逐块编辑、支持主题换肤；`custom-html` 是兜底，不可结构化编辑。

### 6.2 常用 props 格式

| 模块 | 关键 props | 格式 |
|------|-----------|------|
| `heading` | `text` / `level`(h1-h3) / `color` / `align` / `variant`(normal\|hero) / `highlight` / `desc` / `eyebrow` |
| `text` | `content` / `size` / `color` / `align` |
| `button` | `label` / `bg` / `color` / `radius` / `href` / `align` |
| `image` | `src` / `height` / `radius` / `objectFit` / `width` |
| `navbar` | `logo` / `menus`(`标签\|锚点` 每行一条) / `variant`(solid\|ghost) |
| `feature-list` | `title` / `columns` / `items`（见 6.3）/ `variant`(normal\|bento) |
| `card-list` | `title` / `subtitle` / `columns` / `items`(`图片\|标题\|描述\|链接`) / `variant`(normal\|modern) |
| `article-list` | `title` / `moreText` / `items`(`日期\|分类\|标题\|摘要`) / `variant`(normal\|cards) |
| `number-counter` | `items`(`名称\|数字\|后缀`) / `variant`(normal\|strip) / `animate` |
| `contact-form` | `title` / `description` / `button` / `formId` |
| `carousel` | `slides`(`图片地址\|说明` 每行一条) / `height` / `interval` |

### 6.3 图标列表 `items` 的两种格式

**新格式（推荐）**：JSON 数组字符串，每条可带图片或符号：

```json
"[{\"icon\":\"/fkw/crm.jpg\",\"title\":\"专业团队\",\"desc\":\"多年行业经验\"},{\"icon\":\"🚀\",\"title\":\"快速响应\",\"desc\":\"贴心服务\"}]"
```

- `icon`：以 `http` / `/` / `data:image/` 开头渲染为图片，否则渲染为 Emoji/符号，留空显示序号。
- 旧格式 `"标题|描述"` 纯文本仍然兼容（图标显示序号）。

## 7. 图片与静态资源

- 图片放在 `site/public/<模板名>/` 下，引用路径写绝对路径 `/<模板名>/xxx.jpg`。
- **重要**：Next.js 构建产物不会动态读取构建后新增的 `public` 文件。新增图片后必须：
  ```bash
  cd site && npm run build
  ```
  然后重启 site 服务，否则公开站图片 404。
- 图片建议压缩到单张 500KB 以内，整个模板资源控制在 3MB 内。

## 8. 校验清单（提交前逐项确认）

- [ ] `id` 全局唯一，小写中划线
- [ ] 所有必填字段齐全，**尤其 `tags` 是数组**
- [ ] `preview` 是 5 个合法值之一
- [ ] `cover` 是完整 CSS gradient
- [ ] `schema.version` = 1
- [ ] `schema.root.type` = `container`
- [ ] 所有节点 `id` 全树唯一
- [ ] 所有节点 `type` 都在注册表中
- [ ] 所有节点 `props` 匹配对应模块的 propertySchema
- [ ] `items` 多行文本的分隔符是 `|`，每行一条
- [ ] 图片资源已在 `site/public/` 且已重新 build
- [ ] 编辑器打开正常，画布无报错节点
- [ ] 发布测试站，公开站渲染正常、图片不 404
- [ ] 已执行 `npm run seed` 同步数据库

## 9. 常见错误与排查

| 现象 | 原因 | 解决 |
|------|------|------|
| 模板中心白屏 | 缺 `tags` / `tags` 不是数组，搜索时 `join()` 抛错 | 补齐 `tags: []` |
| 模板卡片缩略图错乱 | `preview` 值非法 | 改成 5 个合法值之一 |
| 画布节点显示占位/不渲染 | 节点 `type` 拼错或未注册 | 核对第 6.1 节模块清单 |
| 节点内容为空或异常 | `props` 键名/格式不匹配 | 对照第 6.2 节 |
| 公开站图片 404 | 新增图片后没重新 build site | `cd site && npm run build` 并重启 |
| 数据库里看不到新模板 | 没执行 seed | `cd server && npm run seed` |
| 改了 catalog 但后台没变 | 前端缓存 / 未刷新 | 刷新页面；必要时重启 web-admin dev |

## 10. 自动化校验建议

目前模板**没有自动校验**，全靠人工核对，这也是白屏事故的根因。建议新增一个校验脚本
（如 `scripts/validate-templates.mjs`），在提交或 seed 前运行，检查：

1. 必填字段是否存在、类型是否正确
2. `preview` 是否为合法枚举
3. `schema.root.type === 'container'`
4. 递归遍历所有节点：id 唯一、type 已注册、props 键在 propertySchema 中
5. 引用的图片资源文件是否存在

需要的话可在 `packages/core/package.json` 加一条 `"validate:templates": "node scripts/validate-templates.mjs"`。
